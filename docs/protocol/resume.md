# Project の seq と再同期

Project ごとに、永続化に成功した Command の Event バッチへ 1 から連続する `seq` を割り当てる。SQLite の `commit` は Project 状態、Event、監査行を同じトランザクションで書き込み、失敗時はすべてを取り消す。再送判定の基準となるログの記録時刻はサーバーが付与する。コマンドパイプラインは `event.payload.events` に Domain Event の配列を記録し、コミットで返された `seq` を `ack` と配信する `event` に使う。

- `join` の `lastSeq` は、同じ Project の確定状態に適用済みの最大 `seq`。チェックポイントがなければ省略する。
- `encodeJoinReply` は同じ読み取りトランザクションの Project 状態とログを使用する。要求された全バッチが連続し、すべての記録時刻がサーバーの現在時刻から 7 日以内で、再送上限（最大 1,000 バッチとワイヤー上限）に収まれば `joined(mode=events)` を返す。現行の `seq` を指定した場合、差分は空になる。
- カーソル省略、先行したカーソル、再送上限の超過、保持期間外、旧形式のログなどワイヤー上で再送できない場合は `joined(mode=snapshot)` を返す。ストレージエラーやスナップショットのワイヤー上限超過は呼び出し元に返す。再送対象期間を過ぎたログも監査整合性のため SQLite に保持する。
- クライアントは `startSync` と `receiveSync` で接続ごとの確定状態を管理する。連続するバッチだけを適用し、適用済みの `seq` を無視する。欠番では最後の確定カーソルを付けて再度 `join` し、応答まで差分を受け付けない。応答の開始位置が一致しない場合や適用後の状態が不正な場合は、カーソルを省略してスナップショットを要求する。`ack` では確定カーソルを進めない。

RoomManager（#40）は `joined` を送信してからその `seq` より新しい配信を同じ接続に流す。コマンドの保存と配信は #41、クライアントでの接続管理と同期ストアへの組み込みは #48 が担当する。クライアントはアクティブな接続から届くメッセージを受信順に処理する。
