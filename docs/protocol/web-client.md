# WebSocket クライアント

有効な Project ID を持つプロジェクト・ボードの URL では、同じオリジンの `/ws` に接続する。ロビーとレイアウトプレビューは接続しない。Project 間の移動では前の接続を閉じる。同じ Project の中でボードを移動しても接続は維持する。接続にはタブ内で Project を開くたびに生成した ID を使い、再接続中は同じ ID を保持する。表示名の編集と Project の一覧はロビー（#47）が担当する。

- 接続後に `hello` と `join` を送り、`joined` から確定状態を構築する。切断後は 500 ms から最大 15 秒まで指数的に待ち時間を延ばして再接続する。参加後に接続が 15 秒間続いたら待ち時間を 500 ms に戻す。再接続の `join` には最後に適用した `seq` を含める。完全なスナップショットを要求している間は、前回の状態を表示に使い、再接続時もスナップショットを要求する。ポリシー拒否やプロトコル違反の場合は再試行を止める。
- Zustand のストアでは、確定状態と未確定 Command を分けて保持する。画面用の状態は確定状態に適用可能な未確定 Command を重ねる。拒否された Command のみを外し、現在の version が通知された場合はスナップショットを取り直す。送信済みの作成 Command を含む可能性がある新しいスナップショットを受け取った場合、確認が届くまで該当する仮の作成結果を画面から外す。
- 一度確定状態を取得した後は、再接続中の Command も最大16件まで保留できる。未確認の Command は再参加後に同じ ID で送る。実際の保存と ID による冪等性は #41 が担当する。#40 の Room は Command を明示的に拒否する。

現在のシェルでは接続と保存待ちの状態を表示する。編集操作からの Command 発行は後続のカード・キャンバス実装が行う。

確定状態に適用できない未確定編集もサーバー応答までは確定待ちに残す。拒否後に編集内容を手動で再適用するためのドラフト UI は、カードの編集操作を導入する段階で扱う。
